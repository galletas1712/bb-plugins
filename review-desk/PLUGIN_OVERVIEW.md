# Review Desk

A GitHub pull request review page with the original conversation and inline comments.

- Conversation shows the PR description, comments, reviews, review threads, and timeline events.
- The front page is a repository grid ordered by latest GitHub PR activity. Repository dropdowns contain standalone PRs and collapsed stacks. Phones use one column with whitespace between repositories, while wider panels use multiple columns. Disclosure choices survive live refreshes and reordering.
- A minute-by-minute prefetch pass prepares all visible open PRs with two workers, including merge actions, descriptions, comments, patches, and Markdown content. TanStack Query retains page and component data across navigation and refreshes it without blanking the view. Saved PR pages are prefetched from the repository grid. The initial page response hydrates cached components together. A bounded SQLite read cache persists merge actions and immutable file data across reloads. Merge confirmation still fetches fresh GitHub options. Independent 15-second status scans batch up to 50 PRs per request and track closing and reopening without waiting for Git or conversation work. Git operations are serialized per repository and do not prune other tools' worktrees.
- Changes, Conversation, and Commits share a compact PR header with inline review/merge actions and one repository breadcrumb. The file toolbar offers Source, Rendered, and Source + Rendered icons for Markdown. The combined view has a saved resizable divider and automatic source/block scroll synchronization. Rendered changes use green/red highlights without label rows. Source line numbers remain, with no plus/minus change markers. Display preferences live in the PR overflow menu. Narrow views show one pane and restore the combined preference when widened. The toggleable file explorer shows both old and new locations for moved files.
- Resolved and outdated threads share collapsed dropdowns, with each thread expanded manually. Every comment can be shown or hidden, and replies appear beneath their parent. PR descriptions can be edited with GitHub permissions; comments and replies can only be edited by their author. Repository files are read-only.
- Submit review opens a dialog to send pending comments with a comment, approval, or request for changes. Private notes stay local until added to a review.
- Merge buttons name the action allowed by the repository and target branch rules, defaulting to GitHub's preferred method for the viewer when permitted. Multiple methods share one split button with a dropdown. Confirmation lists the destination branch and affected PRs, including open downstack layers of native stacks. Submission rechecks the head, scope, method, and permissions. GitHub enforces repository rules and reports asynchronous success or failure. Reviews without a visible summary use compact activity rows instead of empty comment boxes.
- GitHub history is fully paginated. File-level and outdated comments remain visible when they cannot be placed on a current diff line. Refresh failures are surfaced and retried.
- Commit navigation and PR stacks retain their individual diffs and comments. File and stack sidebars toggle independently, default to hidden on narrow layouts, and remember explicit open or closed choices. Open layers appear in repository groups and open on demand. Closed and merged PRs, and stacks with no open layers, are hidden. Visible stack counts, positions, and totals exclude completed layers. Stacks have one removal control for the entire stack. Membership and PR metadata refresh automatically, including when opened layers leave the stack. A shared icon shows open, approved, and draft PRs throughout the UI. Each PR shows its added/deleted line totals, and stack summaries sum their PR totals. Pure file moves add no lines to the counts.

The host worker uses authenticated `gh` and git on the repository's machine. Authored open PRs are discovered across repositories every 15 seconds, including drafts, and listed without creating worktrees until opened. Closed or merged PRs leave the automatic list while local drafts remain stored. Explicit removal is remembered. The server caches GitHub data and stores review state in SQLite. The frontend uses BB navigation and Pierre diffs. Existing migrations and user-authored data are preserved.
